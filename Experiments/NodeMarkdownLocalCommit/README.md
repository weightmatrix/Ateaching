# NodeMarkdown局部提交与保存去重验证

运行 `python3 Experiments/NodeMarkdownLocalCommit/check.py` 与 `python3 Experiments/NodeMarkdownLocalCommit/check-reload.py`。

- 第一项提取仓库当前生产模型、结构索引、语义摘要、包清洗及局部/完整追踪函数，比较结果；图片部分提取实际引用解析、所有权检查、引用计数和暂存/恢复I/O，工作区位置替换为系统临时目录，绝不读取真实学生文件。
- 覆盖改回原文清脏、保留无关脏包、新包标题清空/恢复、来源变化、无所属H3节点、H3升降级修时的索引等价、共享图/同节点重复引用/HTML图、最后引用移除进入暂存、撤销字节恢复、结构替换后重建。
- `results.json` 是固定10节点包、100次局部摘要追踪的合成平均耗时；排除打开、结构索引初始化、全文序列化、布局和实际输入，不能当作端到端速度承诺。
- 第二项提取当前生产异步通知检查、布局比较、保存请求共享函数，以可控读写适配器验证保存期间通知合并、同摘要忽略、元数据单独应用、正文外部更新、本地输入和加载代数竞态、失败后待重试且不自旋、同快照并发一次写/不同快照串行及基线摘要衔接。它验证调度与判断逻辑，不模拟Apple iCloud真实冲突过程或文件协调。

尚存边界：结构变化仍用全量校准；图片引用计数在首次引用变化或失效后重建；图片归属校验仍保留完整安全检查；单个巨大H3包的摘要成本依赖包大小。全文序列化和精确排版不在本轮改造内。实际IME、跨窗口/跨设备iCloud与大文档端到端体验仍需新版实测。
