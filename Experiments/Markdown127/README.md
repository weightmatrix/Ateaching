# #127 普通Markdown输入与语法层

## 实现范围

- TK2仍负责编辑、撤销和排版；旧TK1封存不启用。
- iOS普通输入只修改受影响行的属性；自动续行使用局部字符替换并注册撤销，不再替换全文富文本。输入法组合态不应用样式。停顿350ms/保存/关闭时通过共享commit bridge提交正文。
- iOS打开/外部更新/滚动只装饰可见区域，全文语法在后台生成后裁剪到视口；超长单行不在主线程运行正则/语法样式。
- Mac光标和删除判断直接读textStorage；取消主线程逐行补全全文样式及全文搜索高亮。目录和搜索后台生成，过期结果不应用。
- Swift Markdown 0.9.0（swift-cmark 0.9.0，版本锁见Package.resolved）为共享CommonMark/GFM层：目录、原生代码/粗体/强调/链接、高亮上下文和Web预览语法块均使用它。相同正文解析合并请求，结果缓存有上限，UTF8→UTF16按Unicode标量校正。
- 预览按语法块而非空行分块，引用式链接使用AST已解析目标；原始公式/HTML/自定义标记保留。跨空行显示公式作为扩展合并。KaTeX只扫描更新块。异步预览按请求代次和最新正文校验，包括“输入后又撤回原文”场景。
- 原文为唯一保存数据，不把AST格式化结果写回文件。

## 复现

从仓库根目录运行：

```sh
python3 Experiments/Markdown127/run-syntax-tests.py
python3 Experiments/Markdown126/check-all-tk2.py
python3 Experiments/Markdown126/check-pipeline.py
```

脚本在临时Swift Package中编译生产NormalMarkdownSyntax.swift（Release）；测试代码块空行、引用链接、Setext标题、emoji及长Unicode偏移、代码/公式上下文、转义、多反引号、列表跨空行、可见区裁剪、并发同源解析。再调用项目实际marked.min.js验证语法块的HTML输出。只用合成样例，不读取或改动真实文档。

results.json为共享语法层冷解析耗时，不是打字/滚动延迟，也不是正式App端到端验收；不同机器负载会影响结果。样本为大量短段落，另有长Unicode行正确性用例。第三方许可见THIRD_PARTY_NOTICES.txt。

2026-11-17本次Release冷解析参考：400010字节约195ms，2000050字节约963ms，10000055字节约4501ms。解析在后台，结果不代表输入到绘制延迟，也说明全文语法解析仍是随大小增长的剩余开销。

## 限制与后续

这是消除逐键全文处理及共享语法的首版，不声称任意文件大小下绝对恒定速度。保存和停顿后的源文快照仍读取全文；Swift Markdown仍为全文后台解析，预览仍保留整篇DOM，打开、全局搜索、语义刷新和全量导出仍随文件增长。真正的跨编辑增量AST、预览视口虚拟化、Rope文本存储需要后续单独评估。数学、HTML图片宽度等为现有扩展，不是CommonMark保证；未宣称原生编辑器实现所有GFM视觉排版或交互（如可点击任务框）。

设备上的真人IME、长按选择、多级撤销、跨窗口/iCloud并发、图片与公式编辑，以及400KB/2MB/10MB真实文件输入到绘制延迟仍需实机验收；构建和语法测试不能代替这些验收。
